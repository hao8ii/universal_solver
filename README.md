# 通用网页答题工具（内容匹配版）

这是一个独立的通用答题程序，和原来的 `integrated_version` 分开，原版程序不改动。

目标不是“破解所有网站”，而是尽量覆盖普通网页答题系统：

- 自动识别题干、单选、多选、判断题
- **按题干内容和选项内容匹配题库，不依赖网页上的 A/B/C/D 顺序**
- 题型包括普通 `radio/checkbox`、`label`、`div role=radio/checkbox`
- 支持 iframe、开放的 Shadow DOM
- 题干或选项是图片时，自动截图并用本地中文 OCR 识别
- 自动点击“下一题/下一页”，**不会自动点击“提交/交卷”**
- 登录先尝试通用账号密码填表；遇到验证码、短信验证、扫码登录，用户在打开的浏览器里手动完成即可，程序会继续等待并自动开始

## 快速开始

1. 双击 `安装依赖.bat`（首次使用，需要联网）。
2. 双击 `启动通用答题.bat`。
3. 选择题库文件。
4. 填写网址；账号、密码可填可不填。
5. 点击“启动并自动答题”。

两个 `.bat` 是 GBK 编码 + CRLF 换行保存的——Windows 的 cmd 只认这种格式；
如果用编辑器修改它们，请保持这个编码，否则会重新出现“窗口一闪而逝”的乱码报错。

如果出现验证码或特殊登录：

- 在程序打开的 Chrome/Edge 窗口中手动完成登录；
- 进入答题页后，程序会自动识别题目并开始；
- 也可以点“立即开始当前页”手动触发。

程序只负责答当前页和自动翻页，最后请自己检查并点击提交。

## 题库格式

### Excel（推荐）

至少需要两列：

| 题目 | 答案 | A | B | C | D |
|---|---|---|---|---|---|
| 全面依法治国要坚持什么？ | A | 坚持依法治国和以德治国相结合 | 放弃党的领导 | 只依靠群众运动 | 仅依靠道德教化 |

- `答案` 可以写字母（`A`、`ABD`、`A、C`），也可以直接写答案内容。
- 选项列名支持 `A`、`A.`、`A、`、`A：`、`选项A` 等常见写法。
- **A/B/C/D 列很重要**：程序会把字母答案转换成选项内容，再去网页上按内容匹配。这样即使网页把选项顺序打乱，也能选对。
- 如果只有“题目/答案”两列，且答案是字母，程序无法知道选项内容，会跳过该题并提示。请直接加载 Word/PDF 原题库，或补充选项列。

### Word / WPS / PDF

可以直接加载原始题库文件：

- `.docx`
- `.doc`（需要本机安装 Word 或 WPS 用于转换）
- `.wps`（需要本机安装 WPS）
- `.pdf`（文字版 PDF；扫描图片 PDF 需要先 OCR）

程序会从原题库中保留 A/B/C/D 选项原文，因此最适合选项乱序的答题系统。

## 图片题和 OCR

启用“图片题干/选项使用本地 OCR”后：

- 选项文字是图片：对每个选项区域截图并 OCR；
- 题干是图片：对题干图片截图并 OCR；
- OCR 使用 RapidOCR（本地运行，不上传图片）；
- 第一次 OCR 会加载模型，可能慢几秒。

仍然无法处理的情况：

- 整个题目和选项是一张画在 `canvas` 上的图，页面上没有可点击的选项控件；
- 选项是加密图片、极低分辨率、艺术字、竖排文字；
- 网站使用验证码、行为验证、反爬风控；
- 跨域封闭 iframe 或浏览器禁止访问的组件。

这些情况需要人工处理，不能承诺“任何网站 100% 自动”。

## 匹配规则

1. 题干先做归一化（去空格、标点、题号），再用模糊匹配找题库题。
2. 找到题后，把题库答案字母映射成选项原文。
3. 把答案原文与网页实际选项逐项做模糊匹配，得到应点击的选项。
4. 多选题会勾选所有匹配项，并取消不该勾选的已选项。
5. 判断题按“正确/错误/对/错/√/×/true/false”等语义匹配。
6. 题库没有答案的题会跳过，不会乱选。

## 自动翻页

会按文字和 `aria-label` 查找：

- 下一题、下一页、下一部分、下一章、下一节
- 继续、继续答题
- Next、Continue

明确排除：

- 提交、交卷、完成、结束、保存、返回、上一题

如果按钮是纯图标且没有文字、`title`、`aria-label`，可能识别不到，需要手动翻页。

## 常见问题

### 1. 提示 ChromeDriver 版本不匹配

程序使用 Selenium Manager 自动查找驱动。确认 Chrome 已安装，并且能联网下载对应驱动。也可以先升级 Chrome 或 Selenium。

### 2. 启动了浏览器，但一直提示“等待答题页”

- 确认已经登录；
- 确认当前页面就是答题页，而不是课程目录/考试说明页；
- 点“立即开始当前页”；
- 如果题目在 iframe 里，程序会自动尝试进入 iframe；仍失败时请把页面结构发给开发者适配。

### 3. 选项顺序变了，程序选错

检查题库是否真的包含 A/B/C/D 选项原文：

- 用 Word/PDF 原题库加载；
- 或给 Excel 补上 A/B/C/D 列；
- 只有字母答案、没有选项原文的题库无法在乱序时保证正确。

### 4. OCR 识别不准

- 尽量放大浏览器页面（Ctrl + +）；
- 关闭浏览器缩放插件；
- 换清晰度更高的题库/页面；
- OCR 只用于网页图片，不会修改题库。

### 5. 程序会不会自动提交？

不会。程序只点击“下一题/下一页”，到最后一页会停止并提示手动提交。

## 安全说明

- 密码不会写入 `config.json`，只保存在当前程序内存中。
- 浏览器使用 `browser_profile` 目录保存登录状态；如果公用电脑，请删除该目录。
- 题库和网页内容都只在本地处理；OCR 不上传网络。
- 请遵守目标网站的使用规则，不要用于考试作弊等违规场景。

## 打包成 exe

已经打包好一份可直接使用：`build\通用答题工具.exe`（单文件，约 125 MB，
双击即可运行，首次启动要解压，等几秒）。重新打包：

```bat
.venv\Scripts\python.exe bianyi.py
```

- 默认打成单个 exe（onefile），输出先在 `%LOCALAPPDATA%\ua_build`，
  成功后自动拷回项目 `build\` 目录；
- 想要“启动更快、调试方便”的目录模式：`bianyi.py --onedir`；
- 只看命令不执行：`bianyi.py --dry-run`；加图标：`bianyi.py --icon 图标.ico`；
- Nuitka 会自动使用本机 Visual Studio 编译器，没有时自动下载 mingw64；
  整个过程 10~40 分钟（编译缓存在 `%LOCALAPPDATA%\ua_build`，约 2GB，
  删掉只影响下次打包速度；第二次打包因为缓存会快很多）；
- 项目路径含中文时不能把编译输出指向项目内——MSVC 链接器会报
  LNK1104，bianyi.py 已默认规避；
- 打包后的 exe 运行时，`config.json` 和 `browser_profile` 会生成在 exe 同目录；
- 目标电脑仍需安装 Chrome 或 Edge；首次打开浏览器需联网下载对应驱动。

## GitHub Actions 自动打包

代码推送到 GitHub 后 Actions 会自动打包 exe，无需本机安装 Nuitka：

- 推送到 `main` 分支（改代码即可）：自动打包，exe 在该次运行页面的 **Artifacts** 里下载；
- 推送 `v*` 标签（如 `v1.0.0`）：自动打包并发布到仓库 **Releases**；
- 也可以在 Actions 页面手动触发（Run workflow）。

- 首次构建没有缓存，大约 40~90 分钟；之后有编译缓存会快一些；
- 同一分支只保留最新一次构建（旧的自动取消）；
- 仓库为私有时代价是 Actions 分钟数（Windows 按 2 倍计费，免费额度 2000 分钟/月）；
  设为公开仓库则不限时长免费。
